# Execution rules

1. Define the question and the smallest useful domain result. Consult the executable's verified documentation or source before implementing its parser.
2. Reuse a matching contract. A one-off contract needs no registration. Reusable domain code belongs in its contributor, outside the engine.
3. Call `pump [options] <command> [arguments]`: options first, then the command and its native arguments exactly as for the program. Add callbacks for direct execution; omit them for routing. If the native arguments contain `--`, start with `pump [options] -- <command>`. `Pump-Me` binds options anywhere, so it needs `-ArgumentList` for native arguments.
4. Use `-AsObject` inside the same local script, kept in a variable: `$result = pump -AsObject <command>; if ($result.Outcome -ne 'Success') { ... }`. Inspect the final `Kind = Completion` object (`@($result)[-1]` when a contract writes records), its outcome, completeness and errors. Do not discard failed steps when composing results. **Never write that object to the output**, not even to look at it: it holds the complete capture, the domain `Data` and methods. Return a field you chose, or `$result | Out-OPumper2`, bounded and masked like pump.
5. Only serialize the delivery intended for the AI. YAML is the configurable default. JSON and YAML are complete documents with the completion object last.
6. Output budgets apply to presentation, not to intermediate objects. Continue consuming the source after a preview fills; unknown counts remain null in objects and `Data`. Delivered engine metadata omits default values.
7. No automatic retry or fetch. Preserve timeout, cancellation, parser failure and native failure as distinct diagnostics. Ordinary permissions still apply.
8. Never print raw captures, environment values, progress or full logs. A failed delivery already holds `ExitCode`, `Error.Message` and the masked `Excerpt` (last lines of each stream, `-ExcerptLines` to widen or disable): read them before running anything again. For more, read `Capture` (complete stdout and stderr on every local object, or `Execution.Issues[].Capture` for tasks) inside the local script and put only the needed part in `Data`. Measurement failures do not change the business outcome.
9. A route returns a Result (`New-OPumper2Result`): the complete domain value for `-AsObject`, its own projection for JSON and YAML.
10. A delivery names its stored output in `Recall`. When the delivered result is not enough, read that output (`Get-OPumper2Recall <id> -Grep`, `-From`, `-Lines`) or replay it through a better contract (`Invoke-OPumper2Recall`); run the command again only when its result may have changed.
